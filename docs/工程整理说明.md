# 工程整理说明（Water_2）

本文档用于统一该仓库的目录职责、文件归档规则与日常维护动作。

## 1. 整理目标

- 降低“源码 / 生成文件 / 工具文件”混放带来的维护成本
- 明确哪些文件应进版本库，哪些应忽略
- 统一模型文件更新路径，避免多副本不一致

## 2. 目录职责建议

### 2.1 固件源码（应长期保留并纳入版本管理）

- `Core/Inc`
- `Core/Src`
- `Drivers/`
- `MDK-ARM/*.uvprojx`
- `MDK-ARM/*.uvoptx`（团队如需共享工程选项可保留）
- `Water_2.ioc`

### 2.2 构建与中间文件（应忽略）

- `MDK-ARM/build/`
- `MDK-ARM/Water_2/*.d`
- `MDK-ARM/Water_2/*.crf`
- `MDK-ARM/Water_2/*.o`
- `MDK-ARM/Water_2/*.axf`
- `MDK-ARM/Water_2/*.map`
- `MDK-ARM/Water_2/*.hex`
- `MDK-ARM/Water_2/*.lst`
- `MDK-ARM/Water_2/ExtDll.iex`

### 2.3 训练与模型资产（建议策略）

- 固件侧仅保留**当前部署模型**：`Core/Inc/model_data.h`
- 根目录历史模型副本建议移除或改名归档
- 训练日志、`.pth`、`scaler_*.pkl` 建议统一放在训练工程（如 `Water_Python/outputs`）

## 3. 关键一致性规则

### 规则 A：模型头文件唯一真源

建议仅维护：

- `Core/Inc/model_data.h`

不要并行维护根目录 `model_data.h`，避免版本漂移。

### 规则 B：通信协议变更要同步文档

凡修改包格式（头、尾、校验、指令长度），必须同步更新 `README.md` 的“指令接收状态机”章节。

### 规则 C：引脚调整以 `.ioc` 为准

若变更 GPIO/串口/定时器映射，需同时检查：

- `Core/Inc/main.h`
- `Core/Src/gpio.c`
- `Core/Src/usart.c`
- `Core/Src/tim.c`

## 4. 发布前最小检查清单

1. 编译无错误
2. 心跳 JSON 正常
3. `BoomTest()` 结果 JSON 正常
4. `Core/Inc/model_data.h` 与当前训练版本一致
5. 不包含构建中间文件与临时日志

## 5. 推荐版本标记方式

建议在发布记录中最少包含：

- 固件版本号（FW）
- 模型版本号（MODEL）
- 数据集版本号（DATA）
- 编译时间与提交哈希（可选）

示例：

```text
FW: v1.2.0
MODEL: model_2026-02-19_r3
DATA: shuizhi_v5
```
